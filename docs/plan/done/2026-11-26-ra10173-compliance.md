## Confirmed brief

**What.** Close the RA 10173 gaps that actually exist in this repo, ahead of a
real PESO deployment: account erasure, data export, a server-side registration
consent record, and a retention purge runbook.

**How.** Erasure anonymizes in place and retains de-identified placement records
(ADR-060). Export is a JSON download of the caller's own data. Consent is stamped
by the server at `/auth/provision` (ADR-059). Retention is SQL + cron, not app
code.

**Done when.** New Vitest suites pass in `server/` and the web app, migration 022
is applied and verified with `psql`, and the privacy notice names the erasure and
export routes.

**Out of scope.** The FastAPI/Next.js app reviewed by the legal bot; F2/F3/F4/F9/
F10/F15/F17 from that report (verified already handled or N/A here); DPO
appointment and DPIA content (organizational acts of PESO); hard deletion of
placement records; new dependencies.

**Assumptions.** Statutory placement records are retained de-identified. Terms
state 18+ unless PESO confirms SPES minors. Production copy of the legal documents
is edited through the existing admin legal editor (ADR-053); the repo copy is the
fallback/fresh-DB seed.

## Evidence (audited 2026-11-26)

- Only `POST /api/account/deactivate` exists; it flips `status` and revokes
  sessions, removing no PII (`server/src/routes/account.js:75-116`).
- No export endpoint (`server/src/routes`).
- Terms gate is client-side only (`src/features/auth/__tests__/termsGate.test.jsx`);
  no acceptance is persisted. The old referral opt-in was retired by migration
  021 (another agent's change).
- No scheduled purge anywhere in `server/src`.
- Already handled here: helmet with default CSP and a test, fail-closed CORS with
  tests, Better Auth sessions, SMTP mailer, editable legal documents.
- Foreign keys that make hard delete unsafe: `job_applications` and `education`/
  `work_experience` cascade from role rows; `job_vacancies` cascades from
  employers.

## Risks and residuals

- Deleting `auth."user"` is the only irreversible act; it is deliberate and frees
  the email.
- An unlink failure leaves an orphan file; logged, ops cleanup only.
- Legacy Supabase logout is best-effort. The token cache is cleared first, but if
  Supabase is unreachable a legacy bearer can remain valid upstream until expiry.
  Accepted for the ADR-056 dual window.
- `audit_logs` purge after 12 months, including `account.erase` evidence. Raise
  the window if PESO needs longer proof of erasure.
- Production legal text must still be published through the admin legal editor
  (ADR-053); the repo copy is the fallback/fresh-DB seed.
- `db/migrations/022_nationality.sql` (another agent's change) shares the 022
  prefix and is not in the ledger. Not touched here; resolve before deploy.
- The live-DB integration suite was not run against the app database.
- DPO designation, DPIA, and the breach-notification runbook remain organizational
  acts of PESO; this plan did not implement them.
