# Dark Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a user-controllable, persistent dark mode toggled from every header, with no FOUC and whole-system coverage via global CSS overrides.

**Architecture:** Class-based dark mode on `<html>` (Tailwind v4 `@custom-variant`). A `ThemeProvider` context owns `theme ∈ {light,dark,system}`, persists to `localStorage('theme')`, resolves via `prefers-color-scheme`, applies `.dark` to `document.documentElement`. A no-FOUC inline script sets `.dark` before React mounts. Neutral gray scale is redefined under `.dark`; a global `.dark .bg-white` override flips all surfaces. One shared `ThemeToggle` is rendered by `SiteHeader`, `PublicHeader`, and `PortalLayout`.

**Tech Stack:** React 19, Tailwind v4 (CSS-first), Vite, Vitest + jsdom + Testing Library, lucide-react.

**Spec:** `docs/superpowers/specs/2026-10-18-dark-mode-design.md`

## Global Constraints

- No server, schema, or API change. `db/schema.sql` untouched. No new dependency.
- Light-mode rendered output must stay byte-identical (verified by full test suite).
- Shared-component edits are additive `dark:` classes only; no prop signature changes except none.
- Persist only the UI preference (`localStorage('theme')`), never data.
- Toggle is a real `<button>` with `aria-pressed` and a visible focus ring.

## Review Focus

1. **FOUC:** if the inline script runs after first paint or throws, the page flashes light then dark — test by reading `index.html` script placement and a jsdom smoke test asserting `.dark` is present before `render()`.
2. **System preference while in `system` mode:** `matchMedia` change events must flip `.dark`; a stale listener after switching to explicit `light`/`dark` would wrongly override the user's choice.
3. **localStorage corruption:** an invalid stored value must fall back to `system`, not crash or stick.
4. **`matchMedia` missing in jsdom (older):** guard with `typeof window.matchMedia === 'function'`.
5. **Toggle cycles only light↔dark** (explicit), never `system` — verify `setTheme('system')` is never called from the toggle.

- [ ] **Step 3: Implement `ThemeProvider.jsx`**

```jsx
import { createContext, useCallback, useContext, useEffect, useMemo, useState } from 'react'

const STORAGE_KEY = 'theme'
const VALID = new Set(['light', 'dark', 'system'])

function getStored() {
  try {
    const v = localStorage.getItem(STORAGE_KEY)
    return VALID.has(v) ? v : 'system'
  } catch {
    return 'system'
  }
}

function systemPrefersDark() {
  if (typeof window === 'undefined' || typeof window.matchMedia !== 'function') return false
  return window.matchMedia('(prefers-color-scheme: dark)').matches
}

function resolve(theme) {
  if (theme === 'system') return systemPrefersDark() ? 'dark' : 'light'
  return theme
}

const ThemeContext = createContext(null)

export function ThemeProvider({ children }) {
  const [theme, setThemeState] = useState(getStored)
  const resolved = resolve(theme)

  const setTheme = useCallback((value) => {
    const next = VALID.has(value) ? value : 'system'
    setThemeState(next)
    try { localStorage.setItem(STORAGE_KEY, next) } catch { /* ignore */ }
  }, [])

  useEffect(() => {
    const root = document.documentElement
    root.classList.toggle('dark', resolved === 'dark')
    root.style.colorScheme = resolved
  }, [resolved])

  useEffect(() => {
    if (theme !== 'system') return
    if (typeof window === 'undefined' || typeof window.matchMedia !== 'function') return
    const mq = window.matchMedia('(prefers-color-scheme: dark)')
    const handler = () => setThemeState('system') // re-resolve via resolve()
    // Re-run resolution by bumping state identity is unnecessary: resolved is
    // derived, so force a re-render by setting the same value is a no-op.
    // Instead, subscribe and call a no-op state setter to re-render:
    const rerender = () => setThemeState((t) => (t === 'system' ? 'system' : t))
    mq.addEventListener('change', rerender)
    return () => mq.removeEventListener('change', rerender)
  }, [theme])

  const value = useMemo(() => ({ theme, resolved, setTheme }), [theme, resolved, setTheme])
  return <ThemeContext.Provider value={value}>{children}</ThemeContext.Provider>
}

export function useTheme() {
  const ctx = useContext(ThemeContext)
  if (!ctx) throw new Error('useTheme must be used within ThemeProvider')
  return ctx
}
```

Note: the OS-change handler re-renders via the setter; `resolved` recomputes from `theme` (still 'system') reading the now-changed `matchMedia`. Good.

- [ ] **Step 3: Implement `ThemeToggle.jsx`**

```jsx
import { Moon, Sun } from 'lucide-react'
import { useTheme } from '../hooks/useTheme'

export default function ThemeToggle() {
  const { resolved, setTheme } = useTheme()
  const isDark = resolved === 'dark'
  return (
    <button
      type="button"
      aria-pressed={isDark}
      aria-label={isDark ? 'Switch to light mode' : 'Switch to dark mode'}
      onClick={() => setTheme(isDark ? 'light' : 'dark')}
      className="grid place-items-center w-9 h-9 rounded-lg text-gray-600 hover:text-primary hover:bg-gray-100 dark:text-gray-300 dark:hover:text-white dark:hover:bg-gray-700 focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-primary transition-colors cursor-pointer"
    >
      {isDark ? <Sun size={18} aria-hidden="true" /> : <Moon size={18} aria-hidden="true" />}
    </button>
  )
}
```
